# Polar SDK Upgrade Baseline (v0.4.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `polar-sh/sdk` from `^0.7.0` to `^0.10.0` and ship the package as `v0.4.0` with no public-API changes for users of `danestves/laravel-polar`. All existing wrappers, webhook handlers, and models must behave identically from the outside.

**Architecture:** Bump the SDK dependency, then iteratively reconcile each touch-point against the new typed shapes: webhook payload classes in `ProcessWebhook.php`, model accessors/casts in `Subscription.php` / `Order.php` / `Customer.php`, and any internal `LaravelPolar::*` callers. The plan is TDD-shaped where new behavior is involved (e.g. `prorationBehavior`), and audit-shaped where existing tests already encode the contract that must keep passing.

**Tech Stack:** PHP 8.3, Laravel 11/12, Pest 4, PHPStan (larastan 3), Laravel Pint, `polar-sh/sdk ^0.10.0`, `spatie/laravel-webhook-client ^3.0`.

## Task 13: Write the migration doc

**Files:**
- Create: `docs/migration-v0.3-to-v0.4.md`

- [ ] **Step 1: Create the migration doc**

Create `docs/migration-v0.3-to-v0.4.md` with the following content:

````markdown
# Migrating from v0.3 to v0.4

`v0.4.0` upgrades the underlying `polar-sh/sdk` dependency from `^0.7.0` to `^0.10.0`. The public API of `danestves/laravel-polar` is unchanged — your existing calls to `LaravelPolar::*`, the `Billable` trait, models, and events all continue to work the same way.

## What changed under the hood

These changes happened inside `polar-sh/sdk` and are surfaced here only because you might see them if you reach into `LaravelPolar::sdk()` directly:

- Webhook payload `data` shapes were reshaped for `checkout_*`, `order_*`, `subscription_*`, and `benefit_grant_*` events. The package's `ProcessWebhook` handler has been updated to match; no action required if you rely on the dispatched Laravel events.
- Subscription `update` now accepts an additional `prorationBehavior` enum (`invoice` or `next_period`) on `SubscriptionUpdateProduct`. The default behavior is unchanged. To opt in, set the field on your request body:

  ```php
  use Polar\Models\Components;

  $request = new Components\SubscriptionUpdateProduct(
      productId: 'prod_xxx',
      prorationBehavior: Components\SubscriptionProrationBehavior::NextPeriod,
  );

  LaravelPolar::updateSubscription('sub_yyy', $request);
  ```
- Customer Portal list endpoints (`subscriptions`, `orders`, `licenseKeys`, `downloadables`) no longer accept an `organizationId` filter. The package never exposed that filter, so no user-facing change.
- A new `402` HTTP status can be returned by `subscription->update` in payment-failure cases. It surfaces as a `Polar\Models\Errors\APIException` as today.

## Required user actions

None. Run `composer update danestves/laravel-polar` and your app continues to work.

## Reaching into the SDK directly

If you call `LaravelPolar::sdk()` to reach a Polar endpoint not wrapped by this package, review your code against the [polar-sh/sdk v0.10 release notes](https://github.com/polarsource/polar-php/releases/tag/v0.10.0) for the specific endpoints you use.
````
